# **BÀI 24: REFERENCING VALUES WITH REFS**

## **1\. Vấn đề: Component cần "nhớ" nhưng không phải cái gì cũng cần re-render**

Đến hiện tại bạn đã biết:

const \[count, setCount\] = useState(0);

State có hai đặc điểm quan trọng:

State

│

├── React giữ lại qua các lần render

│

└── State thay đổi

↓

React re-render

Ví dụ:

setCount(count + 1);

→ state thay đổi.

→ React cần render lại vì UI có thể phụ thuộc vào count.

Nhưng bây giờ xuất hiện câu hỏi:

Nếu tôi cần Component **ghi nhớ một giá trị qua nhiều lần render**, nhưng giá trị đó **không dùng để hiển thị UI**, thì sao?

Đây là một trường hợp của:

useRef()

# **2\. useRef() là gì?**

Ví dụ:

import { useRef } from "react";

function Counter() {

const countRef = useRef(0);

}

useRef(0) trả về một object có dạng:

{

current: 0

}

Cho nên:

const countRef = useRef(0);

mental model:

countRef

│

▼

┌───────────────┐

│ current: 0 │

└───────────────┘

Muốn lấy giá trị:

countRef.current

→

0

# **3\. Tại sao cần .current?**

State:

const \[count, setCount\] = useState(0);

ta dùng:

count

Còn Ref:

const countRef = useRef(0);

giá trị nằm trong:

countRef.current

Ví dụ:

console.log(countRef.current);

→ 0.

Muốn sửa:

countRef.current = 10;

Bây giờ:

countRef

│

▼

┌───────────────┐

│ current: 10 │

└───────────────┘

Đây là mutation và với ref thì việc thay đổi .current như vậy là bình thường.

# **4\. Điều đặc biệt nhất: sửa Ref không trigger re-render**

Ví dụ:

&lt;/button&gt;

);

0 → 1

console:

1

Click lần 2:

1 → 2

console:

Click lần 3:

2 → 3

console:

3

Nhưng việc **chỉ thay đổi**:

countRef.current

không yêu cầu React render lại UI.

# **12\. .current thay đổi ngay lập tức**

Ví dụ:

}

Kết quả:

Bạn vừa gán:

ref.current = 5;

thì object đã được mutate.

# **13\. Nó khác State Snapshot**

State:

const \[count, setCount\] = useState(0);

function handleClick() {

setCount(5);

console.log(count);

}

Trong event handler/render hiện tại, count vẫn thuộc snapshot hiện tại.

Nên đừng tư duy:

setCount(5)

ngay dòng kế:

count === 5

Không phải mental model đúng.

Trong khi:

ref.current = 5;

console.log(ref.current);

→ 5.

# **14\. Đừng hiểu thành "State là asynchronous"**

Trong tài liệu có:

State: Bất đồng bộ (Snapshot)

Mình khuyên bạn **không ghi nhớ bằng câu "setState là async"**, vì dễ dẫn đến nhiều hiểu nhầm.

Hãy dùng kiến thức bạn đã học:

**Mỗi render nhận một snapshot của state. Gọi setter yêu cầu React thực hiện một render mới; nó không thay đổi biến state của render hiện tại.**

Ví dụ:

console.log(count); // 0

setCount(5);

console.log(count); // vẫn 0

Không phải đơn giản vì:

"setState chạy chậm"

mà vì:

count

\=

state snapshot của render hiện tại

# **29\. Ref khác State ở điểm nào?**

Nếu interviewer hỏi:

**"What is the difference between useState and useRef?"**

Bạn có thể trả lời:

Both can preserve values between renders, but updating state triggers a re-render while changing a ref's current value does not. State should generally be used for data that affects rendering, while refs are useful for values that need to persist without affecting the UI, such as timer IDs or DOM references.

# **31\. Một lưu ý quan trọng: tránh đọc/ghi Ref trong render**

Ví dụ đừng xây tư duy:

function Component() {

myRef.current++;

return &lt;div&gt;...&lt;/div&gt;;

}

Render của React nên **pure**.

Bạn không nên biến render thành nơi thực hiện side effect bằng cách mutate ref tùy tiện.

Ref thường được đọc/ghi ở những nơi như:

Event Handler

Callback

Effect (học sắp tới)

Ví dụ:

function handleClick() {

ref.current++;

}

hoàn toàn khác với việc mutate tùy tiện ngay trong quá trình render.

Phần tiếp theo của Escape Hatches sẽ cho bạn thấy một ứng dụng cực phổ biến khác: **dùng Ref để tham chiếu và thao tác với DOM element**, ví dụ focus thẳng vào một &lt;input&gt;.

Câu hỏi thắc mắc và câu trả lời  
Được. Chỗ này nếu bạn **chưa hiểu setInterval() trả về cái gì** thì nhìn useRef sẽ rất khó hiểu. Ta tạm quên React, học timer JavaScript trước rồi ghép lại.

## **15.1. Trước tiên: setInterval() là gì?**

JavaScript có:

setInterval(() => {

console.log("Hello");

}, 1000);

Nó có nghĩa:

Cứ mỗi **1000ms = 1 giây**, hãy chạy function này một lần.

Flow:

setInterval(...)

│

▼

Browser đăng ký một timer

│

├── 1 giây → console.log("Hello")

│

├── 1 giây → console.log("Hello")

│

├── 1 giây → console.log("Hello")

│

└── ...

Nó sẽ chạy mãi cho đến khi bạn yêu cầu browser **dừng timer đó**.

# **15.2. Nhưng nếu có nhiều timer thì browser biết dừng thằng nào?**

Ví dụ:

→ mỗi 1 giây

😆

Cho nên khi tạo timer, setInterval() **trả về một ID/handle** để sau này bạn tham chiếu đúng timer đó.

Ví dụ đơn giản hóa:

clearInterval(id);

Đây là lý do ta **phải lưu ID**.
