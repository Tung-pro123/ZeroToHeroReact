# **BÀI 27: YOU MIGHT NOT NEED AN EFFECT**

Bài này cực kỳ quan trọng vì sau Bài 26 bạn vừa học được useEffect, rất dễ rơi vào trạng thái:

"Cái gì thay đổi thì tôi quăng vào useEffect."

Nhưng React muốn bạn làm **ngược lại**:

**Mặc định KHÔNG nghĩ tới Effect. Chỉ dùng Effect khi thực sự cần đồng bộ với thứ bên ngoài React.**

# **2\. Ba nơi đặt logic trong React**

Sau Bài 26 + 27, bạn nên có mental model này:

LOGIC

│

┌─────────────┼─────────────┐

│ │ │

▼ ▼ ▼

RENDER EVENT HANDLER EFFECT

### **Render**

Nếu chỉ cần **tính dữ liệu từ props/state hiện có**:

const fullName = firstName + " " + lastName;

→ tính ngay trong render.

### **Event Handler**

Nếu xảy ra vì **user làm một hành động cụ thể**:

function handleBuy() {

buyProduct();

}

→ Event Handler.

### **Effect**

Nếu component cần **đồng bộ với external system**:

useEffect(() => {

connection.connect();

return () => {

connection.disconnect();

};

}, \[\]);

→ Effect.

Đây là cái khung quan trọng nhất của bài 27.

# **7\. Đây gọi là Derived Data**

Bạn sẽ gặp khái niệm này rất nhiều:

**Derived data = dữ liệu có thể suy ra/tính được từ dữ liệu khác.**

Ví dụ:

firstName + " " + lastName;

fullName được derived từ:

firstName + lastName

Hoặc:

Hoặc:

todos.filter(todo => todo.completed);

Hoặc:

Nếu tính được từ props/state hiện tại thì thường:

Không cần thêm State

↓

Không cần Effect

↓

Tính trong render

# **24\. Nhưng còn một câu hỏi kiến trúc sâu hơn**

Nếu cả cha và con đều phải biết cùng một state, đôi khi còn nên cân nhắc:

**Cha có nên sở hữu state luôn không?**

Ví dụ:

function Parent() {

const \[isOn, setIsOn\] = useState(false);

return (

<Toggle

isOn={isOn}

onChange={setIsOn}

/>

);

}

Con:

function Toggle({ isOn, onChange }) {

return (

&lt;button onClick={() =&gt; onChange(!isOn)}>

{isOn ? "ON" : "OFF"}

&lt;/button&gt;

);

}

Bây giờ chỉ còn **một source of truth**:

Parent

│

│ isOn

▼

Toggle

Đây là pattern **lifting state up** bạn sẽ gặp rất nhiều.
