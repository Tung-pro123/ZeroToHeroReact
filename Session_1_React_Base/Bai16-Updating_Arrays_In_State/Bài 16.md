## 🌟 TỔNG QUAN BÀI HỌC

Trong JavaScript, **Mảng (Array) thực chất cũng là một dạng Object đặc biệt** (được lưu trữ bằng địa chỉ tham chiếu trên bộ nhớ Heap). Do đó, nguyên tắc tối thượng của React vẫn áp dụng nguyên vẹn:

> [!IMPORTANT]
> **QUY TẮC BẤT DI BẤT DỊCH:**  
> **Tuyệt đối KHÔNG ĐƯỢC ĐỘT BIẾN (Mutate) Mảng đang lưu trong State**. Bạn không được gán `arr[0] = ...`, không được dùng các hàm phá hủy mảng gốc như `push()`, `pop()`, `splice()`, `sort()`, `reverse()`. Mỗi khi cập nhật, bạn **phải luôn luôn tạo ra một mảng mới toanh** và truyền vào hàm Setter.

## 1. TỪ ĐIỂN CÁC HÀM XỬ LÝ MẢNG TRONG REACT

Để viết code React chuẩn mực, mọi lập trình viên cần học thuộc lòng bảng phân loại các phương thức của Array trong JavaScript:

| Hành động | Hàm Gây Đột Biến (❌ TUYỆT ĐỐI TRÁNH) | Hàm Tạo Mảng Mới (✅ KHUYÊN DÙNG TRONG REACT) |
| :--- | :--- | :--- |
| **Thêm phần tử** | `push()`, `unshift()` | `concat()`, `[...arr, newItem]` (Spread syntax) |
| **Xóa phần tử** | `pop()`, `shift()`, `splice()` | `filter()`, `slice()` |
| **Thay đổi / Sửa** | `splice()`, `arr[i] = ...` | `map()` |
| **Sắp xếp / Đảo ngược** | `sort()`, `reverse()` | Copy mảng trước: `[...arr].sort()`, `[...arr].reverse()` |

```mermaid

    subgraph "❌ CÁC HÀM PHÁ HỦY MẢNG GỐC (MUTATING)"
        A["Mảng cũ: [A, B, C]"] -->|arr.push(D)| A
        A -->|arr.splice(1, 1)| A
        A -->|arr.reverse()| A
        Note1["Địa chỉ RAM KHÔNG ĐỔI -> React Bailout -> KHÔNG RENDER!"]

    subgraph "✅ CÁC HÀM THUẦN KHIẾT TẠO MẢNG MỚI (IMMUTABLE)"

        B -->|B.filter(x => x !== B)| D["Mảng mới: [A, C]"]

    end
```

> [!WARNING]
> **Cặp đôi nguy hiểm dễ nhầm lẫn: `slice()` vs `splice()`**
> * **`slice(start, end)` (Cắt lát):** Tạo ra một mảng bản sao mới chứa các phần tử được cắt $\rightarrow$ **An toàn 100% cho React**.
> * **`splice(start, count, ...items)` (Vá nối / Phẫu thuật):** Cắt xẻ và biến đổi trực tiếp trên mảng gốc $\rightarrow$ **Kẻ thù số 1 gây lỗi trong React**!

## 2. CÚ PHÁP THAO TÁC MẢNG THỰC TẾ

### 2.1 Thêm phần tử (Dùng Spread `...`)
* **Thêm vào cuối mảng (Thay thế cho `push`):**
  ```javascript
  setArtists([...artists, { id: nextId++, name: newName }]);
  ```
* **Thêm vào đầu mảng (Thay thế cho `unshift`):**
  ```javascript
  setArtists([{ id: nextId++, name: newName }, ...artists]);
  ```

### 2.2 Xóa phần tử (Dùng `filter`)
Hàm `filter` trả về một mảng mới chỉ chứa những phần tử thỏa mãn điều kiện logic:
```javascript
// Xóa nghệ sĩ có id trùng với deletedId
setArtists(artists.filter(artist => artist.id !== deletedId));
```

### 2.3 Thay đổi hoặc cập nhật phần tử (Dùng `map`)
Muốn sửa một phần tử cụ thể trong mảng, dùng `map` để duyệt qua từng phần tử:
```javascript
setCounters(counters.map((count, index) => {
  if (index === targetIndex) {
    return count + 1; // Sửa phần tử được chọn
  }
  return count; // Giữ nguyên các phần tử khác
}));
```

### 2.4 Chèn vào vị trí bất kỳ (Kỹ thuật Cắt - Nối với `slice` & Spread)
Giả sử bạn muốn chèn `newItem` vào vị trí `insertAt = 1`:
```javascript
setArtists([
  ...artists.slice(0, insertAt), // 1. Cắt lấy khúc đầu (từ 0 đến trước insertAt)
  newItem,                       // 2. Chèn phần tử mới vào giữa
  ...artists.slice(insertAt)     // 3. Cắt lấy khúc đuôi (từ insertAt đến hết)
]);
```

### 2.5 Sắp xếp (`sort`) hoặc Đảo ngược (`reverse`) an toàn
Vì `sort()` và `reverse()` làm thay đổi mảng gốc, bạn phải **tạo bản sao nông bằng Spread trước**:
```javascript
const nextList = [...list]; // 1. Tạo mảng sao chép mới
nextList.reverse();         // 2. Thao tác thoải mái trên bản sao
setList(nextList);          // 3. Cập nhật state
```

## 3. CẠM BẪY SỐ 1: CẬP NHẬT OBJECT LỒNG BÊN TRONG MẢNG

Xét đoạn mã nguồn tưởng chừng như đã "bất biến":
```javascript
const [todos, setTodos] = useState([
  { id: 1, title: 'Học React', done: false },
  { id: 2, title: 'Làm bài tập', done: false }
]);

function handleToggle(todoId) {
  // ❌ SAI LẦM NGHIÊM TRỌNG:
  const nextTodos = [...todos]; // Copy nông mảng
  nextTodos[0].done = true;     // ĐỘT BIẾN TRỰC TIẾP OBJECT BÊN TRONG!
  setTodos(nextTodos);
}
```

### 3.1 Tại sao đoạn code trên lại là lỗi Mutation?
Toán tử `[...todos]` chỉ tạo ra một cái mảng mới chứa các **con trỏ tham chiếu cũ**. Bản thân object `{ id: 1, done: false }` bên trong vẫn nằm tại cùng một địa chỉ RAM với mảng ban đầu. Việc bạn sửa `nextTodos[0].done = true` đã phá hủy tính bất biến của Snapshot cũ!

### 3.2 Cách giải quyết chuẩn: Kết hợp `map` và Object Spread
```javascript
// ✅ CHUẨN MỰC 100%: Tạo mảng mới VÀ tạo Object mới cho phần tử cần sửa
setTodos(todos.map(todo => {
  if (todo.id === todoId) {
    return { ...todo, done: !todo.done }; // Tạo object mới
  }
  return todo; // Tái sử dụng object cũ nếu không sửa (Structural Sharing)
}));
```

## 4. DÙNG `use-immer` ĐỂ THAO TÁC MẢNG NHÀN HẠ VÀ TRỰC QUAN

Khi mảng chứa các đối tượng lồng nhau phức tạp, việc viết lồng ghép `map` và Spread có thể gây nhức đầu. Thư viện **Immer** giải quyết triệt để vấn đề này:

```jsx
import { useImmer } from 'use-immer';

const [todos, updateTodos] = useImmer([
  { id: 1, title: 'Học React', done: false }
]);

// 1. Thêm todo (dùng push thoải mái!):
updateTodos(draft => {
  draft.push({ id: 2, title: 'Làm dự án', done: false });
});

// 2. Sửa todo (tìm và sửa trực tiếp!):
updateTodos(draft => {
  const todo = draft.find(t => t.id === 1);
  if (todo) {
    todo.done = true;
  }
});

// 3. Xóa todo (dùng splice thoải mái!):
updateTodos(draft => {
  const index = draft.findIndex(t => t.id === 1);
  if (index !== -1) {
    draft.splice(index, 1);
  }
});
```

## 5. GÓC NHÌN SENIOR: ĐỐI CHIẾU VỚI JAVA STREAM API

Nếu bạn là lập trình viên Java / Spring Boot, bạn sẽ thấy phong cách xử lý mảng bất biến của React tương đồng 100% với **Java 8+ Stream API**:

| Thao tác | JavaScript / React Immutable | Java Stream API (Spring Boot) |
| :--- | :--- | :--- |
| **Lọc danh sách** | `arr.filter(item => item.active)` | `list.stream().filter(Item::isActive).toList()` |
| **Biến đổi phần tử** | `arr.map(item => ({ ...item, count }))` | `list.stream().map(item -> item.toBuilder().count(...).build()).toList()` |
| **Tính tổng / Gộp** | `arr.reduce((sum, item) => sum + item.price, 0)` | `list.stream().mapToDouble(Item::getPrice).sum()` |
| **Tính chất** | Không sửa mảng gốc, trả về mảng mới | Không sửa collection gốc, trả về Stream/List mới |

> [!TIP]
> **Tư duy đồng nhất:** Cả React và Java Stream API đều theo đuổi trường phái **Lập trình hàm (Functional Programming)**: Dữ liệu chảy qua các pipeline biến đổi (`filter`, `map`, `reduce`) một cách thuần khiết và không gây ra side-effects.

## 7. BỘ CÂU HỎI PHỎNG VẤN SENIOR REACT DEVELOPER

### Q1: Phân biệt `slice` và `splice` trong JavaScript? Tại sao trong React chỉ được dùng `slice`?
* **Đáp án:** `slice(start, end)` sao chép một đoạn của mảng và trả về mảng mới mà không đụng chạm đến mảng ban đầu (thuần khiết). Trong khi đó, `splice()` cắt bỏ hoặc chèn trực tiếp vào mảng gốc (đột biến). Trong React State, dùng `splice` sẽ vi phạm luật Immutability khiến component không re-render hoặc sinh ra bug khó lường.

### Q2: Đoạn mã sau có an toàn không: `const next = [...list]; next[0].name = 'New'; setList(next);`?
* **Đáp án:** **Hoàn toàn KHÔNG an toàn**. `[...list]` chỉ sao chép nông tầng mảng. Các object bên trong mảng vẫn trỏ về địa chỉ ô nhớ cũ trên Heap. Dòng `next[0].name = 'New'` đã trực tiếp đột biến object của snapshot hiện tại. Cách sửa chuẩn là dùng `list.map` hoặc `useImmer`.
